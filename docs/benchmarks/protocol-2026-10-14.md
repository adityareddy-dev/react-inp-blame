Protocol dated 2026-10-14 America/Chicago. Publish this document before enumerating or selecting fresh apps. Record the public commit SHA and server-observed publication time in the run manifest. The release base is npm 1.0.0, source tag v1.0.0. This protocol changes no library code.

Freeze released npm version and tarball integrity, source SHA, Node/package-manager versions, OS/CPU/RAM, Chromium build, React/framework versions, build options and interaction list. Record the candidate list and reproducible random selection seed. Select at least three fresh apps and 20 scored interactions per app. Do not replace a difficult app silently, record exclusion cause and replacement order. Synthetic hydration fixtures remain a separate diagnostic cohort. Fixes discovered during a run require a new version and fresh holdout, never regrade a tuned app as fresh.

Accuracy: capture independent Chrome traces, Event Timing and LoAF through a separate observer, React profiling/source evidence for naming, and latest report per interactionId. Count every planned valid interaction, including blank/unknown output. Capture setup failures separately with the complete denominator. Grade whole verdict, name/explanation, kind and blamed milliseconds using the existing definitions, right/wrong/misleading/cannot tell/blank. Milliseconds tolerance is max(10 ms, 20% of trace value). Two blinded reads, adjudicate disagreement in a third read, retain original grades and changes. Grades by Adi's workers remain author-run, not independent validation. If a second qualified reader is unavailable report single-reader provisional grades and defer the final accuracy claim.

Report per-app and pooled denominators, confusion/grade counts, confidence intervals with app clustering or per-app intervals when three clusters are too few, separate dev and production and framework configurations. The old 60% right/10% wrong thresholds may be shown as historical comparison only. No success threshold is a filing conclusion. No dropped verdicts and no accuracy claim for 1.0 before results exist.

Overhead: three production configurations, A library absent, B enabled without overlay, C enabled with overlay, same app/source and independent observer. Verify the actual served library bytes and React production mode, including examples that force development. One warmup discarded then at least 30 paired runs per app/config at normal and 4x CPU, balanced seeded order across A/B/C, fresh contexts and deterministic data. Assert each interaction changed the intended page state. Measure independent INP estimate, interaction durations, load-to-ready, long-frame blocking, long tasks, compressed JS bytes actually delivered per route, plus library stats as secondary self-accounting. Paired deltas, 10,000 seeded bootstrap resamples and 95% intervals. An interval containing zero is inconclusive, not proof of zero overhead. Dev/StrictMode hydration results stay in a separate table. Do not cherry-pick C when B is slower, investigate build variance and report all builds and reruns.

## Fixed selection and grading rules

No fresh candidate has been selected for this protocol. After publication, save a sorted list of eligible repository URLs and pinned commits before looking at their blame output. Rank candidates by ascending SHA-256 of UTF-8 `react-inp-blame-2026-10-14:<repository-url>`. This string is the selection seed. Select the first three eligible apps, retaining the full list, exclusions and replacement order. Eligibility requires a public React production build, deterministic reset, at least ten meaningful interactions, and no previous attribution tuning. Exclude every app named in prior benchmark artifacts as well as hyperdx and kaneo. Freeze 20 distinct interaction cases per selected app before collecting scored output, record the action, reset, expected state change and case ID. Repeated timing runs do not create new accuracy cases.

Grade each case on whole verdict, name/explanation, work kind and blamed milliseconds separately. Right means the independent trace and source support the claimed cause and scope. Wrong means they contradict it. Misleading means a true part of the report still directs investigation toward an unsupported cause, component or scope. Cannot tell means evidence cannot settle the claim. Blank means no usable output for a valid observed interaction. Whole verdict is right only when all material claims are supported, contradicted claims make it wrong, otherwise a misleading causal direction makes it misleading, and unresolved evidence makes it cannot tell. Blank is retained as its own whole-verdict grade. Missing reports never disappear from the denominator.

The two initial readers receive independent evidence and the report without each other's grades. Retain reader identities, whether they are author-affiliated, original grades and adjudication. Do not describe workers for the author as outside readers. Match the independent event, trace window and latest report by interactionId and monotonic timestamps. Missing or ambiguous matching is cannot tell, not a guessed pairing. Record trace-backed duration and signed error for milliseconds, with the tolerance above. Report a missing duration explicitly.

A manifest contains protocol SHA, publication receipt, package version/integrity/gitHead, environment, app commits, lockfile/build/served-byte hashes, candidate list and ranking, interaction IDs, reset assertions, raw artifact paths and SHA-256, capture times, failures, grades, revisions and analysis seed. Setup failures and invalid interactions are separately counted with their exact causes and attempted corrections. Retain every planned case, rerun and exclusion. No silently substituted cases.

For overhead, use balanced blocks containing all six permutations of A/B/C, ordered by SHA-256 of `react-inp-blame-2026-10-14:order:<app>:<cpu>:<block>:<permutation>`. Five blocks yield 30 measured paired runs per configuration and CPU condition after discarded warmups. Pair by block and permutation index. Bootstrap paired run deltas with seed `359`, 10,000 resamples, reporting medians and percentile 95% intervals. Publish per-app accuracy proportions with Wilson 95% intervals and pooled descriptive counts, without treating interactions across three apps as independent evidence of general accuracy.

## Claim boundary

No fresh 1.0.0 accuracy result exists at protocol publication. An API stability release does not establish attribution accuracy, performance improvements, outside adoption or independent validation. These are author-run measurements unless outside replication is separately evidenced. Publish poor results and incomplete cohorts with their actual denominators. Any method amendment is a new dated commit, preserving this version and explaining the change before further scored collection.
